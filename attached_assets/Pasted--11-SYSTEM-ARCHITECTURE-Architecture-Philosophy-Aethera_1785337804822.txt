# 11. SYSTEM ARCHITECTURE

## Architecture Philosophy

Aethera is NOT a chatbot.

It is an AI-powered educational platform.

The architecture must therefore separate

- UI
- Business Logic
- AI
- OCR
- Database
- Storage

into independent modules.

Each module should be replaceable without rewriting the entire application.

Follow Clean Architecture principles.

Presentation Layer

↓

Application Layer

↓

Domain Layer

↓

Infrastructure Layer

Never allow UI components to directly communicate with AI providers.

Never call OpenAI/Gemini directly from React components.

Always use the Backend API.

# 15. Folder Responsibilities

Contains routes.

No business logic.

Reusable UI.

Never fetch data directly.

Business logic.

Database calls.

API calls.

Shared helpers.

Clients.

Utilities.

Every component must satisfy

A component should do one thing.

Examples

UploadButton

ConversationHeader

Do not create giant components over 300 lines.

# 23. API Response Format

Success

{
  "success": true,
  "data": {},
  "error": null
}

Failure

{
  "success": false,
  "data": null,
  "error": {
      "code": "...",
      "message": "..."
  }
}

Always use this format.

Never return inconsistent responses.

# 25. Error Recovery

If OCR confidence >90%

Continue automatically.

If OCR confidence between 70–90%

Attempt correction.

If OCR confidence below 70%

Ask ONE clarification question.

Never ask multiple questions.

---

# 26. Security Rules

Validate every upload.

Reject executable files.

Limit upload size.

Sanitize filenames.

Never expose environment variables.

Never expose API keys.

Never expose prompts.

Never expose internal reasoning.
